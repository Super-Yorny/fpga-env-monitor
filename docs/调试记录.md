## 二、根本原因（最重要的一条）

### ★ Bug #1：I2C 读事务时，主机根本没有把「地址字节」发出去

**位置**：`i2c_master.v` 的 `S_BIT` 状态

```verilog
// 错误写法
2'd0: begin
    if (cur_rw) sda_oe <= 1'b0;        // ← 读方向一律释放 SDA
    else        sda_oe <= ~shifter[7];
end
```

**为什么错**：`cur_rw` 表示"这是读事务"，但一个 I2C 读事务里有两个阶段的 SDA 方向完全不同：

| 阶段            | SDA 由谁驱动                 |
| ------------- | ------------------------ |
| **地址字节（8 位）** | **主机**（无论 R/W 位是 0 还是 1） |
| 数据字节（读方向）     | 从机                       |

旧代码只要 `cur_rw=1` 就在**每个 bit 的 phase0** 释放 SDA，于是地址字节被发成了**全 1（0xFF）**&#x800C;不是 `0x71`。从机看到地址 `0x7F`，当然回 NAK。

**症状表现**：

- 写操作（`cur_rw=0`）完全正常 → **OLED 能点亮、能刷新**
- 读操作永远失败 → **AHT20 读回全 1（0xFFFFF）→ 温度湿度永远不变**

**正确写法**：

```verilog
2'd0: begin
    if (cur_rw && !is_addr) sda_oe <= 1'b0;        // 只有"读数据位"才释放
    else                    sda_oe <= ~shifter[7]; // 地址字节 / 写数据位：主机驱动
end
2'd3: begin
    if (!cur_rw || is_addr) shifter <= {shifter[6:0], 1'b0};  // 地址字节也要移位
end
```

**这个 bug 最迷惑人的地方**：它只影响读、不影响写。而 OLED 是纯写设备，AHT20 必须读——所以 OLED 一直正常，AHT20 一直失败，很容易让人误判成"硬件问题"。

## 三、其他已修复的 Bug（按发现顺序）

### Bug #2：I2C 每条命令被重复发送两次

**现象**：OLED 全黑，但 I2C 每个字节都正常 ACK。

**原因**：`i2c_master` 的 `done` 是单周期脉冲，而调用方在 `done` 之后才撤销 `cmd_wr`，且 `cmd_wr` 在两次 `done` 之间**一直保持高电平**。主机在 `S_PULSE` 后直接回 `S_IDLE`，而 `S_IDLE` 每个时钟都采样命令 → 同一条命令被重复锁存。

总线上实际是：

```
期望：00 8D 14      （控制字 + 电荷泵命令 + 参数）
实际：00 00 8D 8D 14 14
```

`0x8D`（电荷泵使能）的参数被后一个 `0x8D` 顶掉：

```
0x8D & 0x14 = 0x04 ≠ 0x14  →  电荷泵保持关闭 → 面板无 7.5V → 全黑
```

**修复**：在 `S_PULSE` 之后插入 `S_GAP`（一拍空转，不采样命令），让调用方在这一拍里装好下一条命令。

---

### Bug #3：页地址命令只有 6 位

```verilog
wdata <= {3'b1011, page};   // 只有 6 位，零扩展后变成 0x2C+page
```

正确的是 `8'hB0 | page`。旧写法不是合法的"设置页地址"命令，SSD1306 直接忽略 → 8 页数据全写进第 0 页。

---

### Bug #4：ACK 判定极性写反

```verilog
ack <= ~sda_i;                     // ack=1 表示"收到 ACK"（SDA 低）
if (!cur_rw && ack) ack_err <= 1;  // ← 收到 ACK 时反而报错
```

导致 NAK 标志完全相反，诊断信息全部失真。正确应为 `if (... && !ack)`。

---

### Bug #5：读事务时主机误驱动「地址应答位」

```verilog
2'd0: if (cur_rw) sda_oe <= mack;   // 读数据字节才该主机回应答
```

`cur_rw=1` 在"地址应答位"和"数据应答位"两个时刻都成立。**地址应答位必须由从机拉低，主机不能动。** 旧写法让主机自己拉低 → 即使从机不在也读回 0 → 假 ACK，NAK 诊断完全失效。

**修复**：新增 `is_addr` 标志，只有 `cur_rw && !is_addr` 时才由主机回应答。

---

### Bug #6：`wait_ms` 位宽不足导致状态机永久卡死

```verilog
reg [6:0] wait_ms;                        // 最大 127
if (wait_ms >= (MEAS_PERIOD_MS - 1))      // 与 999 比较 → 永不成立
```

条件恒不成立 → 永久停在 `P_IDLE` → 从不触发测量 → 读数停在上电初值 0。

**症状伪装性极强**：屏幕显示 `S00 H00000 T00000`，看起来像"传感器返回全 0"，实际是寄存器初值。这个 bug 误导了后续三轮排查。

**修复**：`reg [15:0] wait_ms`。

---

### Bug #7：湿度换算 20 位乘法溢出

```verilog
humi_x10 <= ({d1, d2, d3[7:4]} * 11'd1000) >> 20;   // 错误
```

Verilog 中 `*` 的结果位宽取**两个操作数的较大者**。左值 11 位、操作数 20 位 → 整个表达式按 20 位计算：

- `raw_h × 1000` 超过 2^20 就溢出回绕
- 一个 20 位的数再右移 20 位 → **恒等于 0**

→ 湿度永远显示 0%，与传感器读数无关。

**修复**：

```verilog
wire [31:0] h_num = raw_h * 20'd1000;   // 32 位中间量
humi_x10 <= h_num[30:20];
```

（温度一直正常是因为 `t_num` 恰好声明成了 `[31:0]`，位宽被拉高）

---

### Bug #8：初始化命令与芯片型号不匹配

| 芯片        | 初始化命令                |
| --------- | -------------------- |
| AHT20     | `0xBE 0x08 0x00`     |
| **AHT10** | **`0xE1 0x08 0x00`** |

模块丝印写 `AHT20`，但实测只有 `0xE1` 能让芯片真正完成校准。发 `0xBE` 时芯片始终处于 busy，会 NAK 所有读地址。

**最终采用 `0xE1 0x08 0x00`。**

---

### Bug #9：测量等待时间不足

触发测量后固定等 80ms 就读。手册标称 75~80ms 是**典型值**，实测 80ms 时芯片仍 busy，会 NAK 读地址 → 读回全 1。

**修复**：等待加长到 **200ms**。

---

### Bug #10（架构性）：在子模块内部读 inout 端口

最初 `i2c_master` 内部这样写：

```verilog
assign sda = sda_oe ? 1'b0 : 1'bz;
wire sda_in = sda;              // 在非顶层模块内部读 inout
```

实测顶层能读到 SDA 高电平，但模块内部的 `sda_in` 读出异常。

**修复**：把三态与回读全部上移到顶层，子模块只收发纯信号：

```verilog
assign aht1_sda   = aht1_sda_oe ? 1'b0 : 1'bz;
assign aht1_sda_i = aht1_sda;      // 顶层读顶层 inout
```

## 四、调试手段（按有效性排序）

### 4.1 总线扫描（最有效的一次）

在初始化之前，从 `0x08` 扫到 `0x77`，记录第一个回 ACK 的地址并显示。

**结果：扫到 `0x38`** → 一举证明：

- AHT20 模块活着、地址正确
- I2C 写路径完全正常（START + 地址字节能通）
- 接线、供电、上拉都没问题

**从此把「硬件坏」这条线彻底排除**，方向转到软件协议。

### 4.2 阶段码（定位到具体哪一步失败）

记录第一次 NAK 发生时状态机的状态：

```
1 = P_INIT（发初始化命令时）
3 = P_TRIG（发触发命令时）
5 = P_READ（发读地址时）
8 = P_BARE（裸读时）
```

**结果：裸读阶段就是 `8`** → 说明连"芯片空闲时读一次"都失败 → 问题必然在"读地址字节本身"，而不是"芯片忙"。

这一步直接把范围缩到 `S_BIT` 的地址发送逻辑，最终定位到 Bug #1。

### 4.3 OLED 当示波器

在 FPGA 内部统计 SDA 被拉低的次数（每 1ms 采样，100ms 汇总），显示 `L<low>/<total>`。

**结果：`L00~L01`** → 证明 FPGA **能**读到 SDA 低电平（回读通路没坏），排除了"回读恒为高"的假设。

### 4.4 裸读测试

初始化之前直接读一次状态字节（此时芯片一定空闲）。

**结果：NAK + 返回 `FF`** → 决定性的证据。

### 4.5 LED 当诊断探针

把 LED2 从"温度告警"临时改成"I2C 是否出现 NAK"：

- 常亮 = 有过 NAK
- 快闪 = 全部 ACK

不用任何仪器就能看通信状态。

### 4.6 OLED 显示原始回码

把传感器返回的字节以十六进制显示在屏幕上：

```
S18 H6C3A2 T4D1B8
│    │       └─ 温度原始值 20bit
│    └───────── 湿度原始值 20bit
└────────────── 状态字节
```

`SFF HFFFFF` 一眼就能看出是"全 1"，而不是靠猜。

## 五、走过的弯路（供后人避坑）

### 5.1 一次性改多个变量

早期版本同时改了 `models` 顺序、求解方法、步长、删模型……结果无法定位是哪个改动起作用。**一次只改一个变量。**

### 5.2 改比较条件时没检查操作数位宽

把截位的 `MEAS_PERIOD_MS[6:0]`（得 104，错但能跑）改成正确的 999，却忘了 `wait_ms` 只有 7 位 → **把能跑的循环改成了死循环**，而且症状（读数全 0）伪装成"传感器返回全 0"，误导三轮排查。

### 5.3 过度相信"看起来对"的推论

把 `S00 H00000 T00000` 解读成"传感器返回全 0"，基于此做了一堆推断。实际是寄存器初值。**凡是异常数据，先确认它是"真实回码"还是"寄存器默认值"。**

### 5.4 在没拿到真实波形/回码前就改代码

最浪费时间的模式：猜测 → 改代码 → 烧录 → 现象不变 → 换一个猜测。

**正确做法**：先加观测（总线扫描、阶段码、原始回码），把"不知道"变成"知道"，再改代码。

### 5.5 硬件排查顺序

这次把硬件也查了个遍（都正常），但顺序可以更高效：

```
1. 万用表通断：目标脚 ↔ 模块脚（查断路）
2. 万用表通断：VIN ↔ GND（查短路）
3. 万用表电压：VIN = 3.3V
4. 万用表电阻（20k档）：SDA/SCL ↔ 3.3V，应有 4.7k/10k（查上拉）
5. 逻辑分析仪：看波形（可选，但最直接）
```

**这次实测：上拉 4.7kΩ 存在、供电 3.3V、线路全通、无短路——全部正常，问题确实在软件。**

## 六、关键数据记录

### AHT20/AHT10 数据格式

7 字节：

```
d0   = 状态字节（正常值 0x18 = 已校准 + 空闲）
d1,d2,d3[7:4] = 湿度 20bit
d3[3:0],d4,d5 = 温度 20bit
d6   = CRC8
```

换算：

```
湿度 %RH × 10 = raw_h × 1000 >> 20
温度 ℃ × 10  = raw_t × 2000 >> 20 − 500
```

### 命令一览

```
初始化      0xE1 0x08 0x00
触发测量    0xAC 0x33 0x00
读地址      0x71（= 0x38<<1 | 1）
写地址      0x70（= 0x38<<1 | 0）
```

### 典型读回值

```
S18 H6C3A2 T4D1B8
   └ 湿度 raw = 0x6C3A2 = 443298 → 443298×1000/2^20 = 422.7 → 42.3%RH
    温度 raw = 0x4D1B8 = 315832 → 315832×2000/2^20−500 = 102.4 → 10.2℃
```

### J8 40pin 扩展口引脚（手册表 3-12）

| J8    | 网络        | 球   | 本工程用途            |
| ----- | --------- | --- | ---------------- |
| 1     | GND       | —   | —                |
| 2     | 5V0       | —   | —                |
| 15    | EX_IO_7N  | Y12 | **AHT20 #1 SDA** |
| 16    | EX_IO_7P  | W12 | **AHT20 #1 SCL** |
| 17    | EX_IO_8N  | U12 | **OLED SDA**     |
| 18    | EX_IO_8P  | T12 | **OLED SCL**     |

| 37/38 | GND       | —   | 地                |

> 注意：AHT20 用 Pin15/16、OLED 用 Pin17/18（调试期间做引脚 A/B 测试时互换，之后沿用）。  
> 改接线必须同步修改 `constraints/env_monitor.fdc`。

## 七、工具与环境备忘

### PDS（紫光同创）

- 安装路径：`C:\pango\PDS_2022.2-SP1-Lite`
- 命令行编译：`pds_shell.exe -file build.tcl`
- 约束语法（PDS 专用，**不要用 ISE/Vivado 语法**）：
  ```
  define_attribute {p:<端口>} {PAP_IO_LOC}      {<球名>}
  define_attribute {p:<端口>} {PAP_IO_DIRECTION} {Input|Output|Inout}
  define_attribute {p:<端口>} {PAP_IO_VCCIO}     {3.3}
  define_attribute {p:<端口>} {PAP_IO_STANDARD}  {LVCMOS33}
  define_attribute {p:<端口>} {PAP_IO_PULLUP}    {TRUE}
  ```
- IOBUF 原语：`GTP_IOBUF`（端口 `O`=回读 / `IO`=引脚 / `I`=输出 / `T`=三态使能，T=1 高阻）  
  ⚠️ 本次实测：用它替换手写三态后 OLED 反而点不亮，未采用。

### 逻辑分析仪（24MHz 8 通道克隆版）

- 丝印与软件通道对应：**丝印 CH1 = 软件 Channel 0**
- 排针布局：上排 `CH2 CH4 CH6 CH8 GND`，下排 `CH1 CH3 CH5 CH7 CLK`  
  **GND 在上排最右端**，和 CH1（下排最左）离得很远，容易漏接
- 软件：Saleae Logic 1.2.18（`Logic+Setup+1.2.18.exe` 带驱动）  
  下载：`https://downloads.saleae.com/logic/1.2.18/Logic+Setup+1.2.18.exe`
- 必须接 GND，不接 GND 所有通道都是平线
- 采样率 1~2 MS/s、时长 ≥1 秒（传感器每秒才通信一次）
- 探头接法：**并联旁听，不能串接**，也不能拔掉原线；母头套分析仪，公头插到与目标点**导通**的面包板孔
